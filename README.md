# ITN Partner Desk

An independent prototype of an operations tool for a tokenization General Manager. It answers one question: **which partner should we prioritize, what stops it from becoming operational, and how will we know a launch is commercially successful?**

**Live demo:** https://jm5333.github.io/itn-partner-desk/

> Independent prototype · Synthetic data · Based on Alpaca's public documentation. Not affiliated with or endorsed by Alpaca. All partners, requests, volumes and fees are fictional. Internal workflows and thresholds are proposed.

## What's inside

| Tab | What it shows |
|---|---|
| Weekly brief | KPIs, decisions needed this week (with recommendation, owner and deadline), risks, milestones, next actions |
| Partner pipeline | Activation funnel, partner drill-down (confirmed facts vs. suspected cause), readiness checklist |
| Conversion queue | Mint and redeem requests with real public statuses (`pending`, `completed`, `rejected`), age flags, simulated event trails |
| Economics | Modeled contribution by partner with launch delay and volume ramp; fee is a hypothetical input |
| Partner FAQ | Draft partner-facing answers written from the public integration guides |
| How this was built | What comes from public docs, what is proposed, and questions to validate |
